# v0.98 按钮绘制和点击位置回归（后续交付 v0.99）

用户要求先看真机错误画面，再检查代码和统一回归。排查从 `out/device-v0.95-now.png` 开始：导航只绘出侧栏的一部分宽度，收起按钮绘在正文中间，而无障碍点击区域仍在框边；棋盘的默认附魔值为 -1。

## 原因与修正

- WebView 的静态顶部和固定按钮存在绘制缩放与布局坐标脱节。真机同进程实验只为 `header`、`#tabs`、`#collapse` 设置 `translateZ(0)`，尺寸和坐标不变，截图恢复正确；移除即复现，再加入又恢复。截图和指标保存在 `out/device-v0.97-repro.png`、`out/device-v0.97-promoted-confirm.png`、`out/webview-metrics-v097-before.json`、`out/webview-metrics-v097-promoted.json`。
- CSS 为标题、导航、展开和收起按钮使用独立绘制层。保留内部滚动区的裁切，不再继续调整按钮坐标来补偿错误。
- 软件绘制和等待原生布局的尝试均无效，已撤回。固定屏幕 WebView 与外层窗口裁切保留，以统一悬浮／收起模式的窗口几何。
- `if(c.enchantment)` 把负数当作有效附魔，故输出 -1。改为统一格式化，无值、负值和未知枚举不显示，保留有效枚举 0 与社区中文附魔。
- 前一轮的独立内容滚动、游戏风格边签／拖回区、地毯阴影、关注扫描和倍速恢复实现保留；关注位置与真实跨战斗倍速另行记录，不能由界面检查推断成功。

## 验收规则

最终 APK 必须冷启动核对版本和进程，再对照物理截图、无障碍点击边界与实际触摸结果。候选版本的动态调试结果不能代替最终 APK 验收。

v0.98 的冷启动、四页导航、详情返回、上下裁切、框边与框外收起、真实入口点击和悬浮技能展开均有截图／XML，交互序列见 `out/device-ui-events-v0.98.json`。检查技能展开的即时截图时发现原生窗口尚未升高时会短暂截断技能；稳定后完整，但该过渡问题继续在 v0.99 修正，故本轮最终交付不是 v0.98。

v0.99 在原生窗口确认目标高度后才显示技能行，收起时立即隐藏；增加回归避免旧高度下显示技能。16 项 Node/MCP 通过，`out/tests-v0.99.log`。最终设备证据见 `out/delivery-audit-v0.99.json`。

检查范围：四页导航、详情返回、长列表上下裁切、框边和框外收起、展开入口、悬浮技能、长按移动、拖回区域及阴影。布局默认值 -1 用回归和真实快照核对。15 项 Node/MCP 测试通过，日志 `out/tests-v0.98.log`；资源未变，沿用本轮已通过的 6 项资源／卡框检查。

WebView 调试仅在启动前存在 `bpp_ui_debug` 标记时启用。完成排查已移除该标记，交付正常关闭调试入口。
